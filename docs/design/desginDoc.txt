这是一份完全**摒弃 UI 视觉、排版与布局描述**，纯粹聚焦于底层逻辑、协议架构、数据流转与工程实现的 Swarm Editor 核心功能点具现化技术需求说明（简体中文版）：

---

### 1. 物理进程与守护线程管理引擎 (Daemon Process Lifecycle Management)

* **进程异步拉起与监控**：系统底层（Go 后端）必须具备调用本机操作系统 API 能力，动态拉起并常驻管理 `claude-code`、`gemini-cli`、`aider` 等实体二进制 CLI 进程。
* **资源指标动态追踪**：后端需定时轮询并捕获上述进程的系统物理指标：`PID`（进程标识符）、`CPU 使用率`、`RSS 内存占用`，并将其结构化为 JSON 数据向状态机同步。
* **I/O 管道控制接管**：必须非阻塞地接管每个实体进程的 `stdin`（标准输入）、`stdout`（标准输出）与 `stderr`（标准错误）管道，实现数据流的实时双向读写。

### 2. 高频日志数据流控与环形缓冲 (High-Frequency Log Ring-Buffering)

* **数据缓冲区上限控制**：针对底层进程高频吞吐的日志（如编译、静态检查日志），全局状态管理层必须为每个进程维护一个固定容量的**内存环形缓冲区（Ring Buffer）**，默认上限为 5000 行，超出时自动覆盖旧日志。
* **频率节流与渲染优化**：后端向前端推送日志数据流时，必须建立节流阀（Throttling）机制，限制最大更新帧率（例如 30Hz~60Hz），防止突发巨量日志导致系统通信或客户端线程阻塞。

### 3. 多 Git Worktree 物理文件系统同步 (Multi-Git Worktree File Sync)

* **多工作区路径索引**：系统需支持并行维护多个独立的 Git Worktree 物理磁盘路径索引，确保各个 Agent 进程能在不同的代码分支工作区同时操作。
* **操作系统级文件监听**：利用底层内核事件监听（如 macOS 的 FSEvents / Linux 的 inotify），当底层 Agent 进程对物理磁盘文件进行写入时，异步捕获变更事件并动态更新文件的 Git 状态标签（Modified / Added / Deleted）。

### 4. MCP 能力加载与工具链寻址路由 (MCP Tooling & Skill Resolution)

* **配置文件动态解析**：系统开机时自动加载并解析 `mcp.config.json`，完成外部 MCP 服务器实例的初始化、生命周期握手与连线校验。
* **工具调用（Tools API）路由**：将 MCP 服务器暴露的原子能力（如 `filesystem`、`fetch`）转换为标准的工具链。当蜂王发送工具调用指令时，路由引擎需自动寻址到对应的二进制实例并执行。

### 5. ACP / A2A 双层协议流转引擎 (ACP/A2A Dual-Protocol Routing Engine)

* **ACP（Agent Control Protocol）任务链分解**：系统接收到人类下发的全局目标（Goal）后，由主控进程（蜂王）通过 ACP 协议将 Goal 分解为基于有向无环图（DAG）的任务节点链。
* **A2A（Agent-to-Agent Protocol）补丁对等传输**：当 `gemini-cli` 完成逻辑规划后，不通过磁盘中转，直接在内存中将代码 Patch 通过 A2A 对等协议传输给 `claude-code` 进程，系统需维护该 A2A 通信 traffic 的完整事务（Transaction）日志。

### 6. 人类介入特权拦截器 (HITL Interception & Exception Gateway)

* **敏感/高风险指令捕获**：后端进程控制内核必须实时解析子进程发出的所有指令。一旦检测到敏感操作（如执行写入磁盘、特权 Shell 命令 `rm` / `make build` / 外部网络请求），必须触发特权拦截。
* **异步流水线挂起锁定**：触发拦截后，系统必须**锁定当前进程的 `stdin**`，将该任务节点状态变更为 `BLOCKED`，全局异步调度流水线原地挂起，暂停向下执行。
* **信号解锁与回滚机制**：
* 若接收到外部传入的 `Approve` 数据包，则释放阻塞锁，将指令回填至进程的 `stdin` 管道继续执行。
* 若接收到 `Reject` 数据包，则直接终止（Kill）该进程链，并清除内存缓冲区，触发当前事务回滚。



### 7. 代码变更双缓冲与自动校验 (Code Change Double-Buffering & Verification)

* **虚拟 Patch 缓冲区对比**：Agent 生成的代码 Patch 在正式写入物理分支前，必须存放在内存的影子缓冲区（Shadow Buffer）中，进行 AST（抽象语法树）层面的增量变更计算与代码 Diff 对比，保留人类的撤销特权。
* **自动编译与 Linter 诊断**：代码物理写入磁盘后，后端自动触发底层内置的编译校验工具链（如 Linter、单元测试脚本）。若校验失败，自动捕获错误行号与异常堆栈，并原路通过 ACP 协议反馈给蜂王，启动自主修复循环。
